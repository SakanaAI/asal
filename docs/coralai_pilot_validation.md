# Coralai Pilot Validation

Validation commands and checks for saved artifacts, pilot runs, and reproduced scores using the shared format in `docs/coralai_pilot_contract.md`. Current validation results are recorded in `results/week8/validation/README.md`.

## Files

- Format guide: `docs/coralai_pilot_contract.md`
- Contract validator: `scripts/validate_coralai_contract.py`
- Pilot artifact validator: `scripts/validate_coralai_pilot.py`
- Validation summary: `results/week8/validation/README.md`

## Setup and format checks

Run these checks from the repo root in a Python environment with Torch, NumPy, Pillow, and `jsonschema`. Validation loads checkpoints on CPU without initializing Taichi or downloading CLIP.

```sh
python -m unittest discover -s tests -p 'test_coralai*.py'
python scripts/validate_coralai_contract.py config configs/coralai_pilot.default.json
python scripts/validate_coralai_contract.py result examples/coralai_pilot_result.json
```

The file `examples/coralai_pilot_result.json` only checks the schema format and does not point to real artifact files. Use a `result.json` generated by the runner for the artifact checks below.

## Check a pilot run

Replace `RUN_ID` with the folder name of a completed pilot run:

```sh
python scripts/validate_coralai_pilot.py \
  data/raw/pilot/RUN_ID/result.json \
  --output results/week8/validation/RUN_ID.json
```

What this command checks:

- Manifest format, required checkpoint files, completed step counts, and step log rows.
- Grid shape, finite 14-channel substrate tensors, and integer genome IDs.
- Run metadata settings to see which config values were recorded by the simulation.
- Final image rendering (`substrates/coralai.py`), requiring an exact pixel match with the saved PNG.
- Final checkpoint entropy (`scripts/score_entropy.py`), matching stored metrics within `1e-9`.

The output report sets `simulation_rerun: false` and `clip_recomputed: false` because it checks saved files rather than running a new simulation or loading CLIP. It also checks that `population.pkl` exists without unpickling it. Save validation reports outside the input run directory. The script exits with `0` if all checks pass and `1` if any check fails.

## Reproduce saved results

Run these commands on the local Week 6 checkpoints to reproduce the saved images and scores without overwriting the files in `results/week7/`:

```sh
python substrates/coralai.py \
  data/raw/runs/coral_dev_20261001_174547/checkpoint_0001000/substrate.pt \
  --output data/raw/validation/week8/coralai_frame.png

python scripts/score_entropy.py \
  data/raw/runs/coral_dev_20261001_174547/checkpoint_0001000/substrate.pt \
  --output data/raw/validation/week8/coralai_entropy.json

python scripts/compare_entropy.py --output data/raw/validation/week8/entropy

python scripts/score_coralai.py \
  --image data/raw/validation/week8/coralai_frame.png \
  --prompt "branching colonies" \
  --output data/raw/validation/week8/coralai_clip_score.json
```

Notes:

- `scripts/score_coralai.py` runs on CPU and requires the pinned ASAL, JAX, Flax, and Transformers packages plus access to the CLIP model weights.
- `scripts/compare_entropy.py` accepts `--runs` if your saved run folders are in a different directory.
- Keep the existing `1000` checkpoint label when reporting older runs, since the legacy runner loop index and saved step count can differ by one.

## Compare default and candidate runs

To compare a search candidate against the default configuration, run both with the same seed, grid size, step count, hardware settings, prompt, and entropy bin width in separate output folders. Pass the name of the searched parameter to `--parameter`:

```sh
python scripts/validate_coralai_pilot.py \
  data/raw/pilot/CANDIDATE_RUN/result.json \
  --baseline data/raw/pilot/DEFAULT_RUN/result.json \
  --parameter infra_decay \
  --output results/week8/validation/default_vs_candidate.json
```

What this comparison does:

- Rejects the comparison if any config settings differ selain the searched parameter and `output.root`.
- Validates the artifacts for both runs.
- Recomputes entropy for both runs and reports the difference (`candidate - baseline`).
- Reports the stored CLIP target-loss difference (`candidate - baseline`) when both manifests include CLIP scores, where a negative value means the candidate improved over the baseline.
- Checks whether the recorded software and hardware provenance fields match between the two runs.

## Validation checklist

- Run the headless runner on the default config and confirm the settings reach the simulation.
- Validate the generated `result.json`, final checkpoint, and rendered image.
- Rerun the same configuration and record any variation in CLIP scores or entropy.
- Compare the best search candidate against the default run using matching settings and entropy functions.
- Record any runner, model setup, or reproduction issues alongside the results.
